# ltvb-apps — the server manager for ltvb.nl

A small Rails app (served at **apps.ltvb.nl**) that creates, deploys and manages
every site on server.ltvb.nl. It replaced Plesk, which was removed from this box
on **2026-09-06**: there is no control panel any more, and no licence.

## What it owns

| Concern | Before | Now |
|---|---|---|
| Web tier | Apache + Passenger, vhosts generated by Plesk | `ltvb-nginx` (`/etc/ltvb/nginx`), server blocks rendered by this app |
| App servers | Passenger, reloaded via `tmp/restart.txt` | Puma in one `ltvb-app@<fqdn>.service` per app |
| PHP | `plesk-php*` + Plesk's FPM pools | distro `php8.{2,3,4}-fpm`, pools at `/etc/php/<v>/fpm/pool.d/ltvb-<fqdn>.conf` |
| Certificates | Plesk's Let's Encrypt extension | certbot, http-01 over the shared webroot, all 22 lineages on `authenticator = webroot` |
| Mail | `plesk_virtual` + Plesk SASL | postfix with plaintext maps in `/etc/postfix/ltvb/`, dovecot LMTP + `passwd-file` |
| Databases | Plesk-managed MySQL | distro MariaDB |
| Root operations | `plesk bin …` via a sudo bash wrapper | `ltvb-agentd` over a unix socket (see `deploy/agent/README.md`) |

## The deploy recipe (what `DeployRunner` automates)

1. **Provision** (`create` only, served kinds): `dir.ensure` the log directory →
   write the nginx site **without** TLS → reload → `certbot.issue` → rewrite the
   site **with** TLS → reload → install and enable the app's systemd unit.
   The two-phase site write is not optional: the vhost names certificate files,
   `nginx -t` fails on files that do not exist yet, and the challenge can only be
   answered by a site that is already serving.
2. **Fetch code**: `git clone` / `git reset --hard`, or an uploaded tarball.
3. **Secrets**: write `config/master.key` and `.env` (stored encrypted here).
4. **Gems**: `bundle install` under the app's rbenv Ruby (`/opt/rbenv`) — the
   system Ruby lacks headers and native gems fail against it.
5. **Databases**: `db:prepare` against the app's MariaDB database (the manager itself uses the `apps` database on the shared server, holding its own tables plus Solid Cache/Queue/Cable).
   A shared or external primary is never auto-migrated; that is a separate button.
6. **Assets**: `SECRET_KEY_BASE_DUMMY=1 rails assets:precompile`.
7. **Restart**: `systemd.restart` on the app's unit (Rails), or `fpm.reload`
   (PHP/Laravel), or nothing (static). **Not** `tmp/restart.txt` — see below.
8. **Verify**: HTTP-check the live site over loopback with its own Host and SNI.

## App kinds

- **rails** — Puma in `ltvb-app@<fqdn>.service`, nginx proxying to a unix socket.
- **laravel / php** — nginx + a per-site php-fpm pool.
- **static** — served off disk; no app server to restart.
- **cron** — no vhost; scheduled jobs only.
- **repo** — a plain checkout at a custom path (e.g. the shared `ui-components`),
  pulled and then built by configured follow-up commands. No vhost, no unit.

## Architecture

- Runs unprivileged as `ltvb` under Puma. Non-root steps (git, bundle, rails
  tasks, file writes) run directly as that user.
- Every root operation goes through **`ltvb-agentd`** on `/run/ltvb-agent.sock`,
  which validates each call against a declarative schema before anything runs.
  21 verbs; no path, unit name or line of config is ever a parameter. See
  `deploy/agent/README.md` — it is the trust boundary and worth reading first.
- Deploys run as **Solid Queue** jobs (`ltvb-apps-jobs.service`); the live log
  view polls a JSON endpoint.
- **Self-deploy restarts the worker.** Deploying the manager itself ends with
  `jobs.restart`, because the long-lived Solid Queue worker keeps the old job
  code until its service restarts.
- Access is gated by the ltvb SSO (`login.ltvb.nl`) **and** an `ADMIN_EMAILS`
  allowlist — it fails closed.

## Known gotchas

- **A deploy must restart the unit.** `restart!` used to only touch
  `tmp/restart.txt`, which was right under Passenger and means nothing under
  Puma. Deploys reported success while the old code kept serving. It now calls
  `systemd.restart` and a failure fails the deploy.
- **`psacln` and `psaserv` no longer exist.** Plesk's groups became `ltvb-web`
  (gid 1003) and `ltvb-srv` (gid 1002) — same gids, so nothing on disk changed,
  but a unit still naming the old group cannot start at all: systemd exits
  `216/GROUP` before the process ever runs, and because it only bites on the
  *next* restart it looks like an unrelated outage days later. `SystemdUnit::DEFAULT_GROUP`
  and the agent's `SITE_GROUP`/`WEB_GROUP` are the only places these are named.
- **`nginx -t` must pass before a reload, and a cert must exist before TLS.**
  The agent stages, validates, renames and reloads, rolling back on failure —
  but it cannot invent a certificate, hence the two-phase provision.
- **nginx needs its own spool directories.** Without explicit
  `client_body_temp_path` / `proxy_temp_path` / `fastcgi_temp_path`, nginx falls
  back to paths compiled into the binary under `/var/lib/nginx`, which Plesk
  owned. Requests small enough to buffer in memory succeed, so only large POSTs
  fail — a 500 that never reaches the app. Ours are under `/var/lib/ltvb-nginx`.
- **The php-fpm socket path is ours, not Plesk's.** Pools listen on
  `/run/php/ltvb-<fqdn>.sock`. `NginxConfig` rendered Plesk's
  `/var/www/vhosts/system/<fqdn>/php-fpm.sock` for a while; every PHP site
  rendered from it answered 502 because nothing listens there.
- **Templates are root-owned.** `NginxConfig` and `SystemdUnit` read
  `/etc/ltvb/agent/templates`, never the checkout (except in dev/test). A
  template inside the checkout is owned by the uid eight public apps share.
- **`bundle install` must use the rbenv Ruby**, not the system one.
- **Passenger's stringio conflict** is gone with Passenger, but apps that pinned
  `gem "stringio", "3.1.1"` for it can now drop the pin.

## Local development

```sh
bundle install && bin/rails db:prepare
bin/dev        # Procfile.dev: web + dartsass watch
```

Agent calls do not work off-server; the app boots and the UI renders. Note that
`bin/rails test` needs the development/test bundle, which the **server** does not
have (`BUNDLE_WITHOUT=development:test`) — run the suite locally.
